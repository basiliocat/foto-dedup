# foto-dedup

[![Python 3.8+](https://img.shields.io/badge/python-3.8%2B-blue.svg)](https://www.python.org/downloads/)
[![License: MIT](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)

[English](README.md) | **Русский**

Набор CLI-утилит для поиска дубликатов файлов на NAS с хранением метаданных в SQLite. Разработан для управления большими фото- и медиатеками, разбросанными по нескольким директориям или резервным копиям.

## Возможности

- **Сканирование файлов** с вычислением MD5 и хранением в SQLite
- **Поиск дубликатов** по md5+size с расчётом потерянного пространства
- **Сравнение директорий** с процентами пересечения
- **Кросс-директорная очистка** с настраиваемыми критериями и интерактивным удалением
- **Детектор порчи данных** для файлов с совпадающим именем+размером, но разными хешами
- **Восстановление битых файлов** — поиск целых копий повреждённых файлов

Без внешних зависимостей — используется только стандартная библиотека Python.

## Быстрый старт

```bash
# Настройка виртуального окружения
./setup.sh

# Сканирование директорий
./run.sh scanner /path/to/photos /path/to/backup

# Поиск дубликатов
./run.sh dupes dupes --db files.db

# Проверка на порчу данных
./run.sh corrupt --db files.db
```

## Установка

```bash
git clone https://github.com/basiliocat/foto-dedup.git
cd foto-dedup
./setup.sh
source .venv/bin/activate
```

Требования: Python 3.8+ (используется только stdlib: `hashlib`, `sqlite3`, `argparse`, `pathlib`).

## Использование

Все модули запускаются через `./run.sh <модуль> [аргументы...]` или напрямую: `python -m fotodedup.<модуль> [аргументы...]`.

### 1. Сканирование файлов

Рекурсивно обходит директории, вычисляет MD5-хеши и сохраняет метаданные в SQLite.

```bash
./run.sh scanner /path/to/dir1 /path/to/dir2 --db files.db --min-size 10240
```

| Параметр | По умолчанию | Описание |
|----------|-------------|----------|
| `--db` | `files.db` | Путь к базе данных SQLite |
| `--min-size` | `10240` (10 КБ) | Минимальный размер файла в байтах |

**Как это работает:**
- Рекурсивный обход директорий, симлинки игнорируются
- MD5 считается блоками по 1 МБ — не грузит RAM на больших файлах
- Инкрементальное сканирование: пропускает файлы с тем же path+size
- Каждый запуск получает уникальный `scan_id`
- Ошибки чтения логируются в stderr, сканирование продолжается

### 2. Поиск дубликатов

Группирует файлы по совпадению md5+size, сортировка по потерянному пространству (крупные первыми).

```bash
./run.sh dupes dupes --db files.db
```

Пример вывода:
```
--- Group 1/3: 15.2 MB x 3 copies, waste: 30.4 MB [md5: a1b2c3d4...]
  /photos/2020/vacation/IMG_001.jpg
  /backup/photos/IMG_001.jpg
  /nas/unsorted/IMG_001.jpg

Total: 3 duplicate groups, wasted space: 45.6 MB
```

### 3. Сравнение директорий

Показывает пересечение двух деревьев директорий — сколько файлов общих и что уникально для каждой.

```bash
./run.sh dupes compare /photos /backup --db files.db
```

Пример вывода:
```
Directory A: /photos
  Files: 1200, Total size: 18.5 GB
  Unique content keys (md5+size): 1100

Directory B: /backup
  Files: 800, Total size: 12.0 GB
  Unique content keys (md5+size): 750

Common (same md5+size): 600 files, 9.2 GB
Only in A: 500
Only in B: 150

Overlap: 54.5% of A is in B
Overlap: 80.0% of B is in A
```

### 4. Кросс-директорная очистка

Находит дубликаты между директориями с настраиваемыми критериями и предоставляет интерактивный режим удаления.

```bash
# Только отчёт (по умолчанию)
./run.sh cleanup --db files.db

# Интерактивное удаление
./run.sh cleanup --db files.db --delete

# Отключение отдельных критериев
./run.sh cleanup --db files.db --no-name --delete
```

| Параметр | По умолчанию | Описание |
|----------|-------------|----------|
| `--db` | `files.db` | Путь к базе данных SQLite |
| `--no-name` | включено | Отключить сопоставление по имени файла |
| `--no-size` | включено | Отключить сопоставление по размеру |
| `--no-md5` | включено | Отключить сопоставление по MD5 |
| `--delete` | выкл | Включить интерактивный режим удаления |

По умолчанию все три критерия объединяются по AND: файлы должны совпадать по имени, размеру и MD5. Можно ослабить проверку, отключив критерии флагами `--no-name`, `--no-size` или `--no-md5`.

**Режим отчёта** показывает пары директорий с контекстом:

```
=== /photos/2020  vs  /backup/2020 ===
  Dir A: /photos/2020
    Files: 150, Size: 2.3 GB
    Parent (/photos): 1200 files, 18.5 GB
    Duplicates: 45 files, 800.0 MB

  Dir B: /backup/2020
    Files: 200, Size: 3.1 GB
    Parent (/backup): 800 files, 12.0 GB
    Duplicates: 45 files, 800.0 MB

Total: 5 directory pairs, 120 duplicate files, potential savings: 1.8 GB
```

**Интерактивный режим** (`--delete`) предлагает выбор для каждой пары:

```
Action? [a] Delete from A  [b] Delete from B  [s] Skip  [q] Quit
```

- Файлы удаляются с диска
- Удалённые файлы помечаются в БД (`deleted_at`) для аудита
- Повторный запуск после частичного удаления безопасен — удалённые файлы исключаются

### 5. Детектор порчи данных

Находит файлы с одинаковым именем и размером, но разными MD5-хешами — признак порчи данных, тихого bitrot или неполного копирования.

```bash
./run.sh corrupt --db files.db
```

Пример вывода:
```
--- 1/2: photo.jpg (4.9 KB), 3 copies, 2 different hashes ---
  [a1b2c3d4] /photos/2020/photo.jpg
  [a1b2c3d4] /backup/2020/photo.jpg
  [e5f6a7b8] /nas/unsorted/photo.jpg

Total: 2 groups, 5 files with potential corruption
```

Файлы группируются по имени+размеру и сортируются по размеру (крупные первыми). Укороченный MD5-префикс позволяет быстро увидеть, какие копии совпадают, а какие отличаются.

### 6. Восстановление битых файлов

Поиск целых копий повреждённых файлов по метаданным файловой системы (без базы данных).

```bash
./run.sh badfiles /bad/dir /good/dir --by-name --by-size --same-dir
```

| Параметр | Описание |
|----------|----------|
| `--by-name` | Сопоставление по имени файла |
| `--by-size` | Сопоставление по размеру |
| `--by-name-date` | Сопоставление по имени и дате модификации |
| `--same-dir` | Дополнительно требовать совпадение имени родительского каталога |

Обязательно указать хотя бы один из `--by-name`, `--by-size` или `--by-name-date`.

## Схема базы данных

Все метаданные хранятся в таблице `files`:

| Колонка | Тип | Описание |
|---------|-----|----------|
| `id` | INTEGER | Первичный ключ |
| `path` | TEXT (UNIQUE) | Абсолютный путь к файлу |
| `dir` | TEXT | Путь родительской директории |
| `filename` | TEXT | Имя файла |
| `size` | INTEGER | Размер файла в байтах |
| `md5` | TEXT | MD5-хеш |
| `scan_id` | TEXT | Уникальный идентификатор запуска сканирования |
| `scanned_at` | TIMESTAMP | Дата/время сканирования |
| `deleted_at` | TIMESTAMP | Дата/время удаления (NULL если не удалён) |

**Индексы:** `(md5, size)`, `(dir)`, `(path, size)`.

## Структура проекта

```

├── db.py          # SQLite: схема, init_db(), insert_file(), get_connection()
├── scanner.py     # CLI: рекурсивный обход, MD5 блоками по 1МБ, инкрементальное сканирование

├── test_db.py     # Схема, вставка, upsert, персистентность

├── test_cleanup.py # Миграция, кросс-дубликаты, пары директорий, удаление, интерактив
└── test_corrupt.py # Детектор порчи данных
```
